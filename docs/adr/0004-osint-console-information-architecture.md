# ADR 0004: OSINT console information architecture

- Status: accepted (v1.4.0)
- Date: 2026-11-18
- Deciders: 0thernes
- Supersedes: the top-bar view list and floating legend notes of ADR 0003 (the design system itself stays)

## Context

v1.3 fixed the mechanics: one token set, one window manager, one tab component, axe at 0 violations. The owner's
brief for v1.4 is about the product shape: _"It's basically an intelligence OSINT App Globe."_ The console should
read like an operations tool, with the globe in charge and every other surface in a predictable place.

The v1.3 build still had these structural gaps (measured in `docs/audit/v1.4-ui-audit.md`):

- **Eleven view buttons and nine tool buttons share one top row.** Below 1760 px they collapse to unlabelled icons,
  and the search box shrinks to 140 px. The top bar mixes navigation, tools and search with no grouping.
- **There is no status line.** The user can't see how many rows pass the filters by grade, how fresh the data is,
  whether the live feeds loaded, or the time in UTC and Pacific. Analysts work in UTC and the owner works in Pacific.
- **There is no map legend on the globe.** The pin vs circle rule, which is the most important honesty rule in the
  app, is explained only in Help and the Index.
- **Search finds only cases, reference items and countries.** It can't run commands or toggle layers, so a
  keyboard-first workflow needs about 25 single-letter shortcuts that nobody remembers.
- **There is no activity feed.** The USGS and EONET live layers load silently onto the globe, and there is no list
  of what changed or what the analyst just looked at.
- **The hover tooltip is plain text, and the selected case isn't marked on the globe.** When the dossier is open,
  nothing shows where that case is on the globe.
- **Category colours are consistent between the map and the charts, but category icons don't exist.** Grade
  colours appear in the dossier only.
- **Ergonomics.** Many controls are 24 px (the WCAG minimum), not the 32 px desktop target. There is one density.
  There is no high-contrast option. Help is a hand-written table that has already drifted from the real key handler.
  At 3840x2160 with a device pixel ratio of 1 the chrome is tiny (a dilemma ADR 0003 deferred).

## Patterns studied

These are pattern references only. No assets, code, styles or trade dress were copied.

| Pattern source (category)                                 | Pattern adopted                                                                                         |
| --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Link-analysis / investigation suites (Palantir-style)     | Persistent left **activity bar** of views; object **dossier** on the right; global **omnibox**.         |
| Open-source investigation toolkits (Bellingcat-style)     | Provenance first: source, grade and geolocation basis shown before the narrative.                       |
| ADS-B / flight trackers                                   | **Hover card** with a stable layout; selected object **reticle**; map tool cluster at the globe corner. |
| Conflict live maps (Liveuamap-style)                      | Time-ordered **activity feed** beside the map; click a row to fly there.                                |
| Space situational awareness (Space-Track / LeoLabs-style) | **UTC-first clock** with a local clock; **data-freshness** stamp in the status strip.                   |
| Weather globes (Windy-style)                              | **Bottom timeline dock** with play and a scrubber over a histogram; legend docked to the map.           |
| Multi-source monitoring dashboards (World Monitor-style)  | **Status strip** of counts by class; layers grouped by domain; dense, dark, tabular numerals.           |
| Code editors / command palettes                           | **Ctrl+K** palette over commands, entities and settings; generated shortcut overlay.                    |

## Decision

The layout regions are listed below. The wireframes are in `docs/design/wireframes/`, generated by
`scripts/design/wireframes_v14.mjs` at 1280x800, 1920x1080 and 3840x2160.

1. **The globe is the canvas.** Everything else docks around it. `src/ui/window.js` keeps the free area and
   re-centres the globe in it. The safe area now also excludes the activity bar.
2. **Command bar, top, 56 px.** It holds, from left to right:
   - **Brand.**
   - **Omnibox** (`#search`). `Ctrl+K` and `/` focus it. It has grouped results: Commands, Cases, Places, Layers and
     Reference. `Enter` runs the selected result and `Shift+Enter` filters cases by the text.
   - **Status strip.** It shows the filtered row count per evidence grade, using the colours from `src/grades.js`,
     with the meaning on hover. It also shows the dataset build date (`GM_CATALOG.built`), the latest case date, and
     one dot per live feed: off, loading, ok or error. The strip uses no classification markings, so nothing looks
     like a government document.
   - **Clocks.** UTC and Pacific (`America/Los_Angeles`), in tabular numerals, updated each second.
   - **Utilities.** Screenshot, export, tour, sound, settings and help.
3. **Activity bar, left, 56 px.** It has 13 view buttons in three groups:
   - **Rail:** Layers and Filters.
   - **Analysis:** Wars, Analyze, Hotspots, Charts, Graph and Compare.
   - **Intel:** Reports, Data, Index, Briefings and Feed.

   Each button is a 40 px target with an icon, a tooltip that shows its key, and `aria-pressed` that mirrors its
   window. The element ids are unchanged, so tests and bindings keep working.

4. **Layer and filter rail.** It sits beside the activity bar and collapses. Clicking the active rail button
   collapses the rail, as in a code editor. The filters stay category, grade, era, country and `coord_precision`.
5. **Case dossier, right dock.** The header shows a category icon and colour, a grade chip and a marker chip (pin
   or circle). A **Provenance** block comes first, as a key-value grid: source, grade, `coord_source`, precision
   and coordinates, with coordinates and dates in tabular mono. The narrative, links and related cases follow it.
6. **Timeline dock, bottom.** The existing histogram scrubber and play controls get 32 px targets and grouped
   controls.
7. **Activity feed** (`#feed`, `N`). This window docks right and has two tabs:
   - **Live:** USGS M4.5+ for the past 30 days and NASA EONET open events. Both are fetched only when the feed
     opens, keyless.
   - **Recent:** the dossiers this session opened and the filter changes. Nothing is stored or sent anywhere.
8. **Map legend** (`#legend`, `K`). It sits at the bottom left of the free globe area, collapses, and moves above
   any bottom dock. It shows:
   - the pin and circle glyphs with the exact rule (pin = `exact_site` or `within_1km`; circle = `locality` or
     `region`, radius = uncertainty; never jittered)
   - the cluster badge
   - the categories present after filtering, each with its colour, icon and count
   - the grade colours
9. **Map tools.** A small vertical cluster sits at the top right of the free globe area: home view, lasso, random
   case and legend.
10. **Globe overlays:**
    - a **hover card** with a fixed layout: icon, title, date, category, grade chip, marker kind and `coord_source`
    - a **selection reticle** that follows the open case on the globe each frame
    - **cluster badges**, unchanged in data terms, with a ring in the colour of the majority category
    - labels that stay ground-clamped and decluttered (`src/labels_cesium.js`)
11. **One symbology module** (`src/ui/symbology.js`, pure and unit-tested). It maps each category to its colour and
    icon, and each precision to a marker kind with its wording. The legend, dossier, hover card, omnibox, feed and
    charts captions all read from it, so the map, legend, charts and dossier always agree.
12. **One shortcut registry** (`src/ui/shortcuts.js`, pure and unit-tested). The key handler, the `?` overlay and
    the omnibox commands are generated from it, so Help can't drift from the code.
13. **Ergonomics:**
    - **Density** (Settings or the omnibox): _comfortable_ is the default and makes every control at least 32 px;
      _compact_ goes back to the v1.3 24 px floor. The choice is stored in `gm.ui.density`.
    - **High contrast:** black surfaces, white text, yellow focus and accent, solid lines. The choice is stored in
      `gm.ui.contrast`.
    - **Reduced motion:** the OS setting or Settings switches off fly-to animation and transitions.
    - **4K at DPR 1:** at 2560 CSS px and wider, the token ladder scales by 1.25. This resolves the ADR 0003
      dilemma: 4K panels can be read at desk distance, and the globe still gets more than 60 % of the width.

## Alternatives considered

- **Keep the view buttons in the top bar and add a second row.** Rejected: it costs 48 px of globe height, and the
  buttons still collapse to icons at 1280 px.
- **A hamburger menu for the views.** Rejected: it hides the primary navigation behind a click, and analysts switch
  views constantly.
- **A modal command palette instead of an omnibox.** Rejected for v1.4: the inline omnibox keeps the existing
  `#search` combobox contract, so its tests and ARIA wiring carry over, and it still gives the same Ctrl+K flow.
- **Stack the right docks vertically (dossier above feed).** Deferred: it needs a split-pane mode in the window
  manager. Side-by-side tiling with the 30 % globe floor is already tested.
- **Draw category icons as map glyphs.** Rejected: thousands of icon billboards cost frame time on software WebGL,
  and colour already separates categories on the map. Icons appear in the legend, hover card, dossier, omnibox
  and feed, where they help reading.
- **Classification-style banners (for example, a coloured strip with markings).** Rejected on principle: the
  console must never look like a government document. The status strip shows evidence grades instead.

## Consequences

- Data rules are unchanged and are now visible on the map: pin vs circle in the legend, `coord_source` on hover and
  in the dossier, sources one click away. NUFORC stays private. Gendarmerie is still shown and still excluded from
  analysis.
- New modules:
  - `src/ui/symbology.js`, `src/ui/shortcuts.js` and `src/ui/clock.js`, which are pure and have unit tests
  - `src/ui/console.js`, which runs the command bar, activity bar, legend, map tools, density and contrast
  - `src/ui/feed.js`
  - `css/console.css`, which loads last and holds v1.4 layout tokens only
- `test/ui_audit.mjs --check` now fails on chrome overlaps, clipped controls, nested scroll bars and targets under
  24 px (32 px in the chrome) at all three resolutions. `npm run test:a11y` covers the new views (palette, feed,
  legend, high contrast, compact).
- Cost: about 25 KB of JS and 10 KB of CSS, unminified. Nothing new loads at runtime from a CDN or a keyed API.
