# v1.3 UI audit

Generated by `scripts/audit/ui_audit_report.py` from the measurements of `test/ui_audit.mjs` (Playwright, software WebGL) on the v1.2.0 build. Do not edit by hand: re-run the two scripts.

## Method

- Viewports: 1280x800 (38 views), 1920x1080 (38 views), 3840x2160 (38 views). Device pixel ratio 1.
- Views: the globe with toolbar, rail (layers, filters, collapsed, legend), search, export menu, dossier (plain and PDF 7), Wars, Analysis, Graph, Charts, Briefings, Compare, Help, Settings, Reports, all 7 Data tabs, all 9 Index tabs, Hotspots, cluster dossier, the tour caption and a worst case with three panels open.
- Per view: a screenshot; boxes of every floating element (clipping past the viewport, overlaps, z-index); every scroll container and whether it sits inside another (nested scroll bars); tab markup (roles, aria-selected) and computed style; header controls per panel (minimize, maximize, close), drag and resize; every computed font size, family and line height; paddings against the 8 px grid; click targets under 24 px; glyph icons; truncated labels; and axe-core 4.11 (WCAG 2.0/2.1/2.2 A and AA, including colour contrast), with the WebGL canvas excluded.
- Plus 13 findings from reading the screenshots and the CSS by hand (marked view = manual).
- Each finding appears once, with every view and viewport where it was seen, and exactly one label:

| Label | Meaning |
|---|---|
| bug | does not work or cannot be reached |
| error | wrong value or markup (ARIA, WCAG contrast) |
| issue | inconsistency or rough edge |
| problem | structural gap, no one-line fix |
| dilemma | a trade-off with no free answer |
| conflict | two rules fight over the same pixels |
